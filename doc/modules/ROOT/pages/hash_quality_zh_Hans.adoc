[[header]]
== 哈希质量

[[content]]
[[preamble]]
为了正常工作，哈希表要求提供的哈希函数具有__高质量__，大致意味着它应尽可能均匀地使用其`std::size_t`输出空间，就像随机数生成器那样——当然，不同之处在于哈希函数的值并非随机，而是由其输入参数严格决定。

Boost.Unordered中的闭寻址容器对质量欠佳的哈希函数具有较强鲁棒性，但开放寻址和并发容器对此因素更为敏感。若哈希函数选择不当，其性能可能急剧下降。通常，使用link:../../../../container_hash/index.html[Boost.Hash]提供或生成的函数可确保质量达标，但采用替代哈希算法时需格外谨慎。

本节余下内容仅适用于开放寻址和并发容器。

[[hash_quality_hash_post_mixing_and_the_avalanching_property]]
== 哈希后混合处理与雪崩效应属性

即使提供的哈希函数不符合开放寻址所需的均匀行为，Boost.Unordered容器的性能通常仍可接受，因为库会执行内部__后混合处理__步骤以提升计算哈希值的统计特性。这会带来额外计算开销；若需禁用后混合处理，请按如下方式注解哈希函数：

[source,highlight]
----
struct my_string_hash_function
{
  using is_avalanching = std::true_type; // 指示Boost.Unordered不使用后混合处理

  std::size_t operator()(const std::string& x) const
  {
    ...
  }
};
----

通过设置link:../../../../container_hash/doc/html/hash.html#ref_hash_is_avalanchinghash[`hash_is_avalanching`]特性，我们告知Boost.Unordered：`my_string_hash_function`具有足够质量，可直接使用而无需后混合处理的安全保障。但若哈希函数行为未达声明标准，将面临性能下降风险。

[[hash_quality_container_statistics]]
== 容器统计信息

若全局定义宏`BOOST_UNORDERED_ENABLE_STATS`，开放寻址和并发容器将计算与哈希函数质量直接相关的内部统计信息：

[source,highlight]
----
#define BOOST_UNORDERED_ENABLE_STATS
#include <boost/unordered/unordered_map.hpp>

...

int main()
{
  boost::unordered_flat_map<std::string, int, my_string_hash> m;
  ... // 使用m

  auto stats = m.get_stats();
  ... // 检查统计信息
}
----

`stats`对象提供以下信息：

[source,highlight]
----
stats
     .insertion                                     // 插入操作
               .count                               // 操作次数
               .probe_length                        // 每次操作的探测长度
                            .average
                            .variance
                            .deviation
     .successful_lookup                             // 查找操作（找到元素）
                       .count                       // 操作次数
                       .probe_length                // 每次操作的探测长度
                                    .average
                                    .variance
                                    .deviation
                       .num_comparisons             // 每次操作比较的元素数
                                       .average
                                       .variance
                                       .deviation
     .unsuccessful_lookup                           // 查找操作（未找到元素）
                         .count                     // 操作次数
                         .probe_length              // 每次操作的探测长度
                                      .average
                                      .variance
                                      .deviation
                         .num_comparisons           // 每次操作比较的元素数
                                         .average
                                         .variance
                                         .deviation
----

维护了三类内部操作的统计信息：插入操作（不考虑先前查找键是否存在的操作）、成功查找及失败查找（包括插入元素时内部的查找）。__探测长度__指每次操作访问的link:structures.html#structures_open_addressing_containers[桶组]数量。若哈希函数行为正确：

* 平均探测长度应接近1.0。
* 每次成功查找的平均比较次数应接近1.0（即仅检查找到的元素）。
* 每次失败查找的平均比较次数应接近0.0。
