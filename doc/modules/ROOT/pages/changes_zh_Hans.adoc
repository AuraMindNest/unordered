== 版本 1.89.0

* 已弃用的 `boost::unordered::hash_is_avalanching` 现为 `<boost/container_hash/hash_is_avalanching.hpp>` 中 `boost::hash_is_avalanching` 的 using 声明。请直接使用该头文件。`<boost/unordered/hash_traits.hpp>` 将在未来版本中移除。
* 为开放寻址容器添加 `pull(const_iterator)` 操作。该操作支持通过移动构造高效移除并检索元素。

== 版本 1.88.0

* 使用 Antora 将文档迁移为多页面格式。

== 版本 1.87.0 - 重大更新

* 新增基于节点的并发容器 `boost::concurrent_node_map` 和 `boost::concurrent_node_set`。
* 为并发容器添加 `insert_and_visit(x, f1, f2)` 及类似操作，支持在插入后立即访问元素（相比之下，`insert_or_visit(x, f)` 仅在未发生插入时访问元素）。
* 在特定 `boost::concurrent_flat_set` 操作中实现访问独占锁定，以支持对元素的安全可变修改（{github-pr-url}/265[PR#265^]）。
* 在 Visual Studio Natvis 中，支持使用智能指针分配器的任何容器。只要为智能指针类型编写了适当的 Natvis 自定义点"Intrinsic"函数，此功能适用于任何智能指针类型。
* 为所有容器和迭代器添加 GDB 美化打印器。对于使用智能指针分配器的容器，仅当为智能指针类型本身编写了适当的美化打印器时，此功能才有效。
* 修复开放寻址容器的 `std::initializer_list` 赋值问题（{github-pr-url}/277[PR#277^]）。
* 允许将不可复制的可调用对象传递给并发容器的 `insert_{and|or}_[c]visit` 的 `std::initializer_list` 重载，方法是在内部将可调用对象的 `std::reference_wrapper` 传递给迭代器对重载。


== 版本 1.86.0

* 当头文件 `<memory_resource>` 可用时，添加容器 `pmr` 别名。别名 `boost::unordered::pmr::[容器]` 指代使用 `std::pmr::polymorphic_allocator` 分配器类型的 `boost::unordered::[容器]`。
* 为开放寻址和并发容器配备内部计算和提供受哈希函数质量影响的统计指标功能。此功能通过全局宏 `BOOST_UNORDERED_ENABLE_STATS` 启用。
* 雪崩哈希函数现在必须通过带有嵌入 `value` 常量设为 `true` 的 `is_avalanching` 类型别名进行标记（通常将 `is_avalanching` 定义为 `std::true_type`）。`using is_avalanching = void` 已被弃用，但为向后兼容性仍允许使用。
* 为容器和迭代器添加 Visual Studio Natvis 框架自定义可视化。此功能适用于所有使用原始指针分配器的容器。在此版本中，若容器或迭代器的分配器使用智能指针，则不受支持。此问题可能在后续版本中解决。

== 版本 1.85.0

* 优化 `emplace()` 对 `value_type` 或 `init_type`（如适用）参数的实现，避免创建中间对象。该参数已与预期的中间对象类型相同。
* 优化映射容器上 `k,v` 参数的 `emplace()` 操作，延迟构造对象直至确定应插入元素。当映射的 `key_type` 可移动构造或 `k` 参数为 `key_type` 时触发此优化。
* 修复对具有 `explicit` 复制构造函数的分配器的支持（{github-pr-url}/234[PR#234^]）。
* 修复 `unordered_multimap::find(k, hash, eq)` 的 `const` 版本中的错误（{github-pr-url}/238[PR#238^]）。

== 版本 1.84.0 - 重大更新

* 新增 `boost::concurrent_flat_set`。
* 为并发容器添加 `[c]visit_while` 操作，含串行和并行变体。
* 新增 `boost::unordered_flat_(map|set)` 与 `boost::concurrent_flat_(map|set)` 之间的高效移动构造互操作。
* 为并发容器添加批量访问功能以提升查找性能。
* 添加调试模式机制，用于检测用户代码对并发容器的非法重入。
* 为所有容器及其（非本地）迭代器类型添加 Boost.Serialization 支持。
* 为开放寻址和并发容器添加智能指针支持。这支持了如使用 Boost.Interprocess 分配器在共享内存中构建容器等场景。
* 修复闭散列容器本地迭代器的指针成员操作符错误（{github-pr-url}/221[PR#221^]，致谢 GitHub 用户 vslashg 发现并修复此问题）。
* 自本版本起，`boost::unordered_[multi]set` 和 `boost::unordered_[multi]map` 仅支持 C++11 及以上标准。

== 版本 1.83.0 - 重大更新

* 新增 `boost::concurrent_flat_map`，一种基于开放寻址的快速线程安全哈希映射。
* 加速开放寻址容器的迭代过程。
* 在开放寻址容器中，原无返回值的 `erase(iterator)` 现返回可转换为下一元素迭代器的代理对象。这支持了典型的 `it = c.erase(it)` 惯用法，且当未使用返回的代理对象时不产生性能损失。

== 版本 1.48.0 - 重大更新

此重大变更已转换为使用 Boost.Move 的移动模拟，并更符合 {cpp}11 标准。详见 xref:compliance.adoc[合规性章节]。

容器现满足 {cpp}11 的复杂度要求，但因此会占用稍多内存。这意味着 `quick_erase` 和 `erase_return_void` 不再必需，将在未来版本中移除。

{cpp}11 支持导致部分破坏性变更：

* 相等性比较已更改为 {cpp}11 规范。在具有等价键的容器中，原要求等键组内元素顺序相同才视为相等，现允许其为任意排列。要使用旧行为，请定义宏 `BOOST_UNORDERED_DEPRECATED_EQUALITY`。

* 当待交换的两个容器分配器不等时，swap 行为已变更。原使用相应分配器分配新节点，现若分配器具有成员结构 `propagate_on_container_swap` 且其 `::value` 为 true，则交换分配器。

* 分配器的 `construct` 和 `destroy` 函数现使用原始指针调用，而非分配器的 `pointer` 类型。

* `emplace` 原模拟早期 {cpp}0x 草案中的可变参数 pair 构造函数。因草案移除，现不再支持。其现模拟新的 `piecewise_construct` pair 构造函数——但需使用 `boost::piecewise_construct`。要使用旧式可变参数构造函数模拟，请定义 `BOOST_UNORDERED_DEPRECATED_PAIR_CONSTRUCT`。
