[[changes_release_1_87_0_major_update]]
== 版本 1.87.0 - 重大更新

* 新增基于节点的并发容器 `boost::concurrent_node_map` 和
`boost::concurrent_node_set`。
* 为并发容器新增 `insert_and_visit(x, f1, f2)`
及类似操作，支持在插入后立即访问元素（而 `insert_or_visit(x, f)`
仅在未插入时访问元素）。
* 在特定 `boost::concurrent_flat_set`
操作中实现访问独占锁定，支持元素的安全可变修改（https://github.com/boostorg/unordered/pull/265[PR#265]）。
* 在 Visual Studio Natvis
中支持使用花式指针分配器的任意容器。只要为花式指针类型编写了正确的
Natvis 定制点"Intrinsic"函数，即可适用于所有花式指针类型。
* 为所有容器和迭代器添加 GDB
美化打印器。对于使用花式指针分配器的容器，需为花式指针类型编写专用美化打印器方可生效。
* 修复开放寻址容器的 `std::initializer_list`
赋值问题（https://github.com/boostorg/unordered/pull/277[PR#277]）。
* 允许向并发容器的 `insert_{and|or}_[c]visit` 的 `std::initializer_list`
重载传递不可复制的可调用对象，方法是在内部向迭代器对重载传递可调用对象的
`std::reference_wrapper`。

[[changes_release_1_86_0]]
== 版本 1.86.0

* 当 `<memory_resource>` 头文件可用时，新增容器 `pmr`
别名。`boost::unordered::pmr::[container]` 别名指向使用
`std::pmr::polymorphic_allocator` 分配器类型的
`boost::unordered::[container]`。
* 为开放寻址和并发容器添加内部计算和提供受哈希函数质量影响的统计指标功能，通过全局宏
`BOOST_UNORDERED_ENABLE_STATS` 启用。
* 雪崩哈希函数现在必须通过 `is_avalanching` 类型定义标记（通常将
`is_avalanching` 定义为 `std::true_type`），其内嵌的 `value` 常量设为
`true`。`using is_avalanching = void` 已弃用，但为向后兼容仍允许使用。
* 为容器和迭代器添加 Visual Studio Natvis
框架定制可视化。适用于所有使用原始指针分配器的容器。此版本中，若分配器使用花式指针则容器和迭代器不受支持，后续版本可能解决此问题。

[[changes_release_1_48_0_major_update]]
== 版本 1.48.0 - 重大更新

本次重大变更采用 Boost.Move 的移动模拟，并更符合 C++11
标准。详见link:compliance.html[合规性章节]。

容器现满足 C++11 复杂度要求，但内存占用略有增加。`quick_erase` 和
`erase_return_void` 因此不再必需，将在未来版本移除。

C++11 支持导致部分破坏性变更：

* 相等性比较改为 C++11
规范：含等效键的容器中，原要求等键元素顺序相同才视为相等，现允许互为排列。定义宏
`BOOST_UNORDERED_DEPRECATED_EQUALITY` 可启用旧行为。
* 交换操作在容器分配器不等时的行为变更：原使用对应分配器分配新节点，现若分配器含
`propagate_on_container_swap` 结构且
`propagate_on_container_swap::value` 为 true，则交换分配器。
* 分配器的 `construct` 和 `destroy` 函数现使用原始指针（而非分配器的
`pointer` 类型）调用。
* `emplace` 原模拟早期 C++0x 草案的变参 pair
构造函数，因草案移除而停止模拟。现模拟新的 `piecewise_construct` pair
构造函数（需使用 `boost::piecewise_construct`）。定义
`BOOST_UNORDERED_DEPRECATED_PAIR_CONSTRUCT` 可启用旧变参构造模拟。
