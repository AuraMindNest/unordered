[[header]]
== 并发容器

[[content]]
[[preamble]]
Boost.Unordered 提供
`boost::concurrent_node_set`、`boost::concurrent_node_map`、`boost::concurrent_flat_set`
和
`boost::concurrent_flat_map`，这些哈希表允许不同线程进行并发读写访问，无需用户实现任何同步机制。

[source,highlight]
----
std::vector<int>                    input;
boost::concurrent_flat_map<int,int> m;

...

// 并行处理输入
const int                 num_threads = 8;
std::vector<std::jthread> threads;
std::size_t               chunk = input.size() / num_threads; // 每个线程处理元素数

for (int i = 0; i < num_threads; ++i) {
  threads.emplace_back([&,i] {
    // 计算当前线程处理的输入范围
    std::size_t start = i * chunk;
    std::size_t end = (i == num_threads - 1)? input.size(): (i + 1) * chunk;

    for (std::size_t n = start; n < end; ++n) {
      m.emplace(input[n], calculation(input[n]));
    }
  });
}
----

上例中，线程访问 `m`
时无需同步，如同单线程场景。理想情况下，若工作负载分配到 _N_
个线程，执行速度将比单线程快 _N_
倍——由于同步开销和__争用__（线程等待其他线程离开映射的锁定区域），实践中无法达到此极限。但
Boost.Unordered
并发容器设计为极低开销，通常实现__线性扩展__（即性能与线程数成正比，最高至
CPU 逻辑核心数）。

[[concurrent_visitation_based_api]]
== 基于访问的 API

Boost.Unordered
并发容器的新用户首先会注意到：这些类__不提供迭代器__（技术上不符合 C++
标准中的https://en.cppreference.com/w/cpp/named_req/Container[容器]定义）。因为迭代器本质上是线程不安全的。考虑以下假设代码：

[source,highlight]
----
auto it = m.find(k);  // A: 获取指向键 k 元素的迭代器
if (it != m.end() ) {
  some_function(*it); // B: 使用元素值
}
----

多线程场景中，若其他线程在 A 和 B 之间执行 `m.erase(k)`，迭代器 `it`
可能在 B
点失效。虽有方案可通过锁定元素解决此问题，但易引发高争用和死锁。`operator[]`
存在类似并发问题，因此
`boost::concurrent_flat_map`/`boost::concurrent_node_map`
也未提供该操作。替代方案是通过__访问函数__操作元素：

[source,highlight]
----
m.visit(k, [](const auto& x) { // x 为键 k 的元素（若存在）
  some_function(x);            // 使用该元素
});
----

用户传递的访问函数（此处为 lambda 函数）由 Boost.Unordered
以线程安全方式内部执行，因此可安全访问元素，无需担心其他线程干扰。

但访问函数__不可__访问容器本身：

[source,highlight]
----
m.visit(k, [&](const auto& x) {
  some_function(x, m.size()); // 禁止：访问函数内不能操作 m
});
----

但允许访问其他容器：

[source,highlight]
----
m.visit(k, [&](const auto& x) {
  if (some_function(x)) {
    m2.insert(x); // 允许：m2 是另一个 boost::concurrent_flat_map
  }
});
----

通常，访问函数应尽可能轻量以减少争用并提升并行性。某些情况下，将繁重操作移出访问函数可能更优：

[source,highlight]
----
std::optional<value_type> o;
bool found = m.visit(k, [&](const auto& x) {
  o = x;
});
if (found) {
  some_heavy_duty_function(*o);
}
----

访问机制在并发容器 API 中占核心地位，许多经典操作都有其访问式变体：

[source,highlight]
----
m.insert_or_visit(x, [](auto& y) {
  // 若因存在等价元素 y 导致插入失败
  // 可对其进行操作，例如：
  ++y.second; // 递增元素的映射部分
});
----

注意此例中访问函数可__修改__元素：通常，并发映射 `m` 的操作会根据其
const/非 const 属性授予访问函数对应权限。使用 `cvisit` 重载（如
`insert_or_cvisit`）可显式请求常量访问，可能提升并行性。而并发集合的访问始终为常量访问。

虽然使用频率较低，但并发容器也提供在元素创建后立即访问的插入操作（除等价元素已存在时的常规访问外）：

[source,highlight]
----
  m.insert_and_cvisit(x,
    [](const auto& y) {
      std::cout<< "(" << y.first << ", " << y.second <<") 已插入\n";
    },
    [](const auto& y) {
      std::cout<< "(" << y.first << ", " << y.second << ") 已存在\n";
    });
----

完整访问式操作列表请参阅
link:reference/concurrent_node_set.html#concurrent_node_set[`boost::concurrent_node_set`]、link:reference/concurrent_node_map.html#concurrent_node_map[`boost::concurrent_node_map`]、link:reference/concurrent_flat_set.html#concurrent_flat_set[`boost::concurrent_flat_set`]
和
link:reference/concurrent_flat_map.html#concurrent_flat_map[`boost::concurrent_flat_map`]
的参考文档。

[[concurrent_whole_table_visitation]]
== 全表访问

在无迭代器的情况下，`visit_all` 提供处理容器内全部元素的替代方案：

[source,highlight]
----
m.visit_all([](auto& x) {
  x.second = 0; // 重置元素的映射部分
});
----

在支持标准并行算法的 C++17 编译器中，全表访问可并行化：

[source,highlight]
----
m.visit_all(std::execution::par, [](auto& x) { // 并行执行
  x.second = 0; // 重置元素的映射部分
});
----

遍历可中途中断：

[source,highlight]
----
// 查找给定（唯一）值对应的键

int  key = 0;
int  value = ...;
bool found = !m.visit_while([&](const auto& x) {
  if(x.second == value) {
    key = x.first;
    return false; // 终止遍历
  }
  else {
    return true;  // 继续遍历
  }
});

if(found) { ... }
----

最后一项全表访问操作是 `erase_if`：

[source,highlight]
----
m.erase_if([](auto& x) {
  return x.second == 0; // 删除映射值为零的元素
});
----

`visit_while` 和 `erase_if`
也可并行化。注意：为提升效率，全表访问操作不阻塞容器，这意味着其他线程可能在访问期间插入、修改或删除元素。建议勿对并发容器的全局状态做过多假设。

[[concurrent_bulk_visitation]]
== 批量访问

假设有需在并发映射中查找的 `std::array` 键数组：

[source,highlight]
----
std::array<int, N> keys;
...
for(const auto& key: keys) {
  m.visit(key, [](auto& x) { ++x.second; });
}
----

__批量访问__支持单次操作传递所有键：

[source,highlight]
----
m.visit(keys.begin(), keys.end(), [](auto& x) { ++x.second; });
----

此功能不仅为语法便利：通过一次性处理所有键，可应用内部优化提升性能（参见link:benchmarks.html#benchmarks_boostconcurrent_flatnode_map[基准测试]）。实际上，缓冲传入键值以分块批量访问可能更优：

[source,highlight]
----
static constexpr auto bulk_visit_size = boost::concurrent_flat_map<int,int>::bulk_visit_size;
std::array<int, bulk_visit_size> buffer;
std::size_t                      i=0;
while(...) { // 处理循环
  ...
  buffer[i++] = k;
  if(i == bulk_visit_size) {
    map.visit(buffer.begin(), buffer.end(), [](auto& x) { ++x.second; });
    i = 0;
  }
  ...
}
// 处理剩余键
map.visit(buffer.begin(), buffer.begin() + i, [](auto& x) { ++x.second; });
----

这是延迟与吞吐量的权衡：缓冲会延长键处理时间，但每秒处理量更高。`bulk_visit_size`
是推荐分块大小——更小的缓冲区可能降低性能。

[[concurrent_blocking_operations]]
== 阻塞操作

并发容器可像其他 Boost.Unordered
容器一样复制、赋值、清空和合并。与多数操作不同，这些是__阻塞操作__：执行期间其他线程无法访问相关容器。库自动处理阻塞，用户无需额外操作，但整体性能可能受影响。

另一阻塞操作是__重新哈希__，可通过 `rehash`/`reserve`
显式触发，或在插入时负载达到 `max_load()`
时自动执行。与非并发容器相同，预先预留空间可加速批量插入。

[[concurrent_interoperability_with_non_concurrent_containers]]
== 与非并发容器的互操作性

由于开放寻址容器与并发容器基于相同内部数据结构，它们可高效地通过移动构造与非并发版本互转，反之亦然。

.表 1. 并发/非并发互操作性
[width="100%",cols="50%,50%",]
|===
|`boost::concurrent_node_set` |`boost::unordered_node_set`
|`boost::concurrent_node_map` |`boost::unordered_node_map`
|`boost::concurrent_flat_set` |`boost::unordered_flat_set`
|`boost::concurrent_flat_map` |`boost::unordered_flat_map`
|===

此互操作性适用于多阶段场景：部分数据处理并行执行，其他步骤非并发（或只读）。下例中，我们需要从巨型单词向量构建直方图：填充阶段用
`boost::concurrent_flat_map` 并行执行，结果再转入最终容器。

[source,highlight]
----
std::vector<std::string> words = ...;

// 并行插入单词
boost::concurrent_flat_map<std::string_view, std::size_t> m0;
std::for_each(
  std::execution::par, words.begin(), words.end(),
  [&](const auto& word) {
    m0.try_emplace_or_visit(word, 1, [](auto& x) { ++x.second; });
  });

// 转入常规 unordered_flat_map
boost::unordered_flat_map m=std::move(m0);
----
